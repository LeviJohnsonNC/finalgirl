# Upgrade the story text and poster image models

Verified against the live gateway this turn (45 models offered): the current chains all still work, but better models are now available. `google/gemini-3-pro-image` and the current default chat model `openai/gpt-5.6-sol` are both live.

## What changes for you

- Posters and opening stills get generated by a higher-quality image model — better composition, better text on the poster, closer to a real movie one-sheet. Slower and more expensive per image.
- Intro stories and ending narration get written by a much stronger model, so the prose should be sharper and follow the module-specific rules context (Mort, the Intruders, Wingard scavenging) more faithfully.
- Everything else — the VHS look, streaming text as it is written, rate limits, storage — stays exactly as it is.

## Image model

In `supabase/functions/_shared/models.ts`, put `google/gemini-3-pro-image` at the head of `IMAGE_MODEL_CANDIDATES`, keeping `google/gemini-3.1-flash-image` and `google/gemini-2.5-flash-image` behind it as fallbacks (the `LOVABLE_IMAGE_MODEL` env override stays first).

No other image code changes: the test call confirmed the response carries the image at `choices[0].message.images[0].image_url.url` as a data URI, which `extractImage` in `_shared/aiGateway.ts` already handles, and `generate-scene-image` continues to upload to the `posters` bucket and return a public URL.

Because the pro image model is slower, `generate-scene-image` must not gain any timeout — confirm no abort/deadline is wrapped around the gateway fetch.

## Text model

The text slot moves to `openai/gpt-5.6-sol`. That model is served by the gateway Responses API (`/v1/responses`), not `/v1/chat/completions`, so this is more than a string swap:

1. `_shared/models.ts`: `TEXT_MODEL_CANDIDATES` becomes `openai/gpt-5.6-sol` with the `LOVABLE_TEXT_MODEL` override still honoured. Keep `google/gemini-3.8-flash` as a fallback id, and record which API each id needs.
2. `_shared/aiGateway.ts`: add a Responses-API path used when the resolved model is an `openai/*` id.
   - `streamChat` posts to `https://ai.gateway.lovable.dev/v1/responses` with `stream: true`, `input` built from the system + user text, `store: false`, and no reasoning options (these are one-shot generations; we do not render thinking).
   - It re-emits the upstream SSE as the OpenAI chat-completions frame shape the browser already parses (`data: {"choices":[{"delta":{"content":"…"}}]}`), so `src/lib/streamChatCompletion.ts`, `NowPlaying.tsx` and the ending flow need no changes. Alternatively teach the client to read `response.output_text.delta` — the re-emit is chosen because it keeps the client untouched.
   - `generateText` (shot briefs, visual bible) uses the same endpoint with `stream: true` and accumulates the deltas server-side, per the streaming requirement for that API.
   - `max_tokens`/`temperature` are dropped for this model (it rejects them); length limits move into the prompt text in `_shared/prompts.ts`.
   - Error classification, single retry, and model fallback stay as they are; the Gemini fallback continues to use the existing chat-completions path.
3. Rate limiting, `logUsage()`, and the CORS/guard wrappers in `generate-story`, `generate-ending`, `generate-visual-bible`, `generate-scene-image` are untouched.
